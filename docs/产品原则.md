# ChatArchive 产品原则

ChatArchive 的核心对象是数据源、群和消息。用户需要找到群、看见记录、理解沟通事实，并把授权数据交给自己的分析工具。

## 三个入口

| 入口 | 核心任务 | 操作路径 |
| --- | --- | --- |
| 概览 | 管理所有来源的群目录与覆盖情况 | 搜索群名或编号 → 查看消息量和最近消息 → 进入群 |
| 数据源 | 按平台检查连接并使用数据 | 选择来源 → 群分析 / 记录分析 / 连接状态 |
| MCP 接口 | 授权其他平台查询 | 创建有范围和有效期的密钥 → 配置客户端 → 核对调用 |

取消独立“档案库”：原页面按来源展示档案集合，与数据源重复，增加了一层导航而没有独立任务。“归档质量”也不占主导航；未归档群、缺失名称、无日期和附件状态应出现在对应对象旁。

## 群与记录

飞书优先显示真实群名，保留群编号和连接标签；企业微信群名缺失时明确显示编号。目录包含零消息群，区分已知群与已有归档的群。发言人数按平台账号 ID 去重，不按同名文字合并。

群详情保留群身份与时间范围，提供分析和记录两个视图。趋势、类型、时段、参与情况和高频词都由选定范围内的实际消息计算。点击词语应能到原文，不产生无法追溯的“洞察”。

记录支持关键词、日期、消息类型、分页、原文展开和消息 ID 引用。跨平台分析不自动合并同名员工或群。

## 分析的边界

本轮提供确定性的描述性分析。高频词使用有限样本并显示样本数；它不是话题理解或工作结论。通过 MCP，使用者可让自己选择的 AI 在授权记录上分析，并保留原始证据。未接入模型时不出现假“生成报告”按钮。

## 开源交付

将部署样例、数据适配器、查询层、权限层与前端分开。默认单工作空间、私有数据、只读查询密钥。真实业务凭据、数据和客户环境不进公开包。独立运行路径与生产既有采集器并存，不要求别人复刻本团队的服务器结构。

## 文案与界面

标题直接命名对象和操作。主界面只放完成任务所需的状态、数字、筛选和动作。产品背景、技术选型、实施进度留在仓库。没有保存接口的配置不画开关，未连接的数据源不显示成功状态。缺失值不冒充零，原文不公开到静态文件。
