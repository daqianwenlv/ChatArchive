## 容器验证

环境：Linux amd64，Docker 28.1.1，Compose 2.35.1，Python 3.12.15。使用源码包解压后的代码，创建独立测试项目与全新数据卷；没有使用生产数据或平台凭据。

`scripts/verify_docker.py` 的以下阶段全部通过：

1. 从 Dockerfile 构建镜像，按锁文件的官方 SHA-256 安装依赖。
2. 空白初始化、创建本地账号、导入虚构样例两次，仍为 1 个群、2 条消息。
3. 首次改密、旧会话失效、来源校验、越权拒绝、HTTP 查询和官方 MCP SDK 调用。
4. 重建容器后账号与数据保留，在线生成备份。
5. 恢复到另一个独立数据卷，旧密码及旧接口密钥失效，重设账号后查询和 MCP 正常。
6. 切回原数据卷，原账号和原数据可用。

结束后已确认本次测试容器和测试数据卷均已清理，原有服务继续运行。

本次环境直连 Docker Hub 超时、PyPI 下载缓慢。Python 官方镜像先从可访问 Docker Hub 的机器下载，再导入测试机；Python 包通过清华 PyPI 镜像下载，安装时强制校验官方 PyPI 发行文件哈希。此网络条件与正常直接拉取流程不同，不表示已经验证测试机直连 Docker Hub。

实际使用的官方 `python:3.12-slim` amd64 manifest：`sha256:2b4f19dae3a777dfc3b76730bda1e82e1f66ab2a2686fa93ca78edbfb4f04ffe`。基础镜像标签会更新，后续版本应重新构建和验收。

- 尚无 ARM64 容器实测、大数据量并发压测或独立安全复核。
