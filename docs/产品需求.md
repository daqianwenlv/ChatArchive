# ChatArchive 产品需求

ChatArchive 是自托管的聊天数据管理系统。企业接入授权范围内的沟通记录后，可以找到群、查看消息、理解沟通事实，并通过 HTTP 或 MCP 将数据交给自己的工具。开源交付包含后台、管理界面和适配器规范；客户端配置不会自动部署采集服务。

## 五个主入口

| 入口 | 当前查询预览版 | 下一版增加 |
| --- | --- | --- |
| 概览 | 群名或编号、消息数、来源、参与账号和最近消息，进入群详情 | 授权范围内的采集进度、处理进度与历史缺口 |
| 数据源 | 平台目录、群分析、记录分析、连接状态 | 多个连接实例、凭据配置、群范围、同步补采和清洗任务 |
| 指令台 | 跨群选择、消息筛选、统计与资料清单、即时执行 | 受控模型分析与任务模板 |
| 任务 | 规则保存、日/周/月计划、运行结果、导出、暂停与重跑 | 成员授权、运行治理与自定义保留策略 |
| MCP 接口 | 只读工具、密钥、范围与调用记录 | 服务账号及更多客户端的标准授权 |

原始数据、标准化和数据质量属于后台能力，分别呈现在群、消息和数据源内，不增加独立“档案库”导航。成员与权限、存储和保留策略置于工作空间设置；登录、未获邀请和会话失效有独立状态。

## 成员与管理员的操作

成员登录后只看到自己的工作空间和授权群，进入群可看统计并按日期、关键词、类型查询记录，展开正文与出处。消息引用在编辑和重放后仍指向明确版本。

数据管理员先验证连接主体与权限，再选择群及历史起点。成功连接、群可见、有记录、已处理、媒体完整是不同状态。失败项提供原因与可执行操作；尚无后台能力的功能不显示假按钮。

服务账号只读取授予范围，不继承创建者的浏览器会话。所有者可限定工具、连接、群、期限并撤销访问；前端隐藏不能作为权限控制。

## 统计口径

- 已发现、已选择采集、有记录和有历史缺口的群分别统计，未知覆盖不写成百分之百。
- 消息发生、事件采集、清洗完成与索引更新时间分别记录。
- 拉取条数、重复投递、有效新事件、逻辑消息和消息版本使用不同计数。
- 同一消息由两个确认同身份的连接采入，可有两个来源观察和一个逻辑消息；身份不明时不自动合并。
- 同名账号不自动合并，缺少群名或姓名时保留编号。

## 数据与分析

有效平台负载先归档，标准消息和派生结果可以按规则版本重建。旧系统只有文本的记录标为历史转换数据，不伪装成完整原始报文。附件原件、下载失败、OCR 和模型结果分别保存。

当前分析包括趋势、类型、时段、参与账号和高频词。下一版事项分析记录数据范围、模型目的地、输入版本和证据。聊天里没有完成记录不等于工作没有完成，发言数量不直接作为绩效结论。

## 平台范围

| 平台 | 当前范围 | 后续方向 |
| --- | --- | --- |
| 飞书 | 已有归档与 CLI 可见群 | 独立连接管理、授权历史与增量采集、附件及消息版本 |
| 企业微信 | 既有会话存档库，缺群名时显示编号 | 存档适配器、解密和媒体补偿、授权范围管理 |
| 微信 | 已有历史导入 | 可选设备代理，单独验证设备条件及记录覆盖 |
| 钉钉 | 目录占位，没有采集器 | 验证授权通道与历史能力后实现 |

能接收机器人消息不等于能取得全群历史；群可见不等于消息已采集。实现适配器时复核平台官方接口和权限，声明实际能力与限制。
